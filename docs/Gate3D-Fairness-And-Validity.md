# Gate 3D fairness and threats to validity

The R/W capability table is B1=(0,0), B1-W=(0,1), B1-R=(1,0), B2=(1,1).
B0 is an unauthenticated reference. Receipt acceptance binds a target duty.
Independent witnessing authenticates an observation. Freshness in the frozen
B2 engine additionally depends on its auditor challenge and complete snapshot.
B1-R does not bypass that requirement.

A witness discovery route forwards an existing gateway signature and is usable
by every signed configuration under the same declared collection schedule.
Changing attestation delivery alone cannot insert a gateway checkpoint into
B1-W input. The witness-related conditions share production bytes for each
seed and size. Any acquired evidence change must follow explicit observation,
retention, delivery or exchange.

The pilot pairs seed, complete payment workload, log size, public query sample,
trusted public keys, observer budget and acquisition history across configurations.
R/W typed projections then expose approved capabilities. Equal request limits
do not equalize information, serialized bytes or cryptographic computation.
B2's stricter proof requirements can increase inconclusive outcomes even when
other configurations can observe presence.

The first audit event has an obligation, the second is an independent negative
control. Both are predetermined public queries. The fixed sample avoids quadratic
growth from reauthenticating an entire snapshot for every event. It does not
estimate population-wide false-accusation or detection prevalence. Full experiments
need a predeclared representative sample and weighting.

Actual truth derives from physical write histories, signed-view commitments,
accepted duties and deadlines. Eligibility uses the frozen cryptographic verifier.
Classifiers also use that verifier, so common implementation defects can bias
proof availability and supported detections. The immutable key bootstrap prevents
key discovery from evidence but still requires an authenticated provisioning
channel outside the simulation.

Owner separation is an API/dependency boundary in a trusted process. Hostile
classifiers require isolation from owner replay files, manifests and scoring
objects. Crash behavior is simulated dropped writes and recovery-time retries.
Durable crash recovery, real networks, cross-epoch continuity and operational
key revocation are outside these pilots.

Elapsed measurements include synchronous parsing and verification. Current
classifiers repeatedly authenticate snapshots per query. Their cost reflects
this implementation, with different capabilities and workloads per invocation.
There is no separate production payment throughput or transaction-latency metric.
CPU sharing, frequency changes, tiered JIT, one warmup, two repetitions, GC,
sequential execution and archive caching can materially affect these observations.
Process peak memory is cumulative, so it cannot rank isolated classifier memory.

The negative controls expose the difference between raw guesses and supported
detections. No single aggregate ranking or error-cost weighting is introduced.
Always-inconclusive yields no accusations, but its missed positives remain in
the unconditional detection denominator. Always-accuse cannot manufacture proof.

Recommendation criteria for final benchmarking include representative workload
and obligation distributions, an approved public audit sample, separate or
controlled processes, sufficient warmup and repetitions, predeclared statistical
analysis, memory attribution and deployment-relevant collection costs. Pilot
correctness and replay can be engineering-ready while publication-scale timing
methodology remains Not Ready.
